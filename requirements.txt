# 🎭 BROWSER AUTOMATION & TEST FRAMEWORK

# Playwright — modern browser automation (Microsoft).
# Drives Chromium/Firefox/WebKit headlessly or with UI.
# Why this and not Selenium? Faster, auto-waits, better DX, built-in tracing.
playwright==1.48.0

# Pytest — the de-facto Python testing framework.
# Provides fixtures, assertions, parametrization, plugin ecosystem.
pytest==8.3.3

# pytest-bdd — BDD plugin for pytest.
# Lets us write Gherkin .feature files (Given/When/Then) and map each
# step to Python functions. Enables business-readable tests.
pytest-bdd==7.3.0

# parse — explicit pin so our step-definition validator can use the SAME
# matching semantics pytest-bdd uses at runtime. This library is a
# transitive dep of pytest-bdd, but we pin it explicitly because Agent 2's
# `_phrase_matches()` validator imports it directly to detect the
# `parsers.parse('...{u}...')` + empty quoted value `""` failure mode.
# Without this, the validator silently passes broken code.
parse>=1.20.0

# pytest-playwright — official integration of Playwright with pytest.
# Adds the `page`, `browser`, `context` fixtures and CLI flags.
pytest-playwright==0.5.2

# Allure for pytest — generates rich HTML test reports.
# Captures screenshots, traces, durations, and trends across runs.
allure-pytest==2.13.5

# pytest-html — self-contained single-file HTML report.
# Used by Agent 4 (Runner) for human-readable artifact uploaded to GitHub Actions.
# Read by Agent 5 (Reporter) is via junit.xml, not this HTML.
pytest-html==4.1.1


# ─────────────────────────────────────────────────────────────────────────────
# 🤖 LLM & AGENT ORCHESTRATION
#
# IMPORTANT: All these packages must be on the same major version (1.x).
# Upgrading any one of these requires upgrading all of them together.
# ─────────────────────────────────────────────────────────────────────────────

# LangChain is used ONLY as a provider-agnostic HTTP client. Exactly two
# imports, in agents/llm_client.py:
#     from langchain_openai import ChatOpenAI              (the HTTP call)
#     from langchain_core.messages import SystemMessage, HumanMessage
# No chains, no agents, no tools, no memory. Structured output is enforced by
# Pydantic (model_json_schema -> prompt -> model_validate_json), NOT by
# LangChain, so the layer we actually trust is ours and inspectable.
#
# Deliberately NOT used (see docs/AI_CONCEPTS.md):
#   langgraph  - our state machine is the Jira label sequence
#                (ai-ready -> ai-processed -> human-approved -> ai-coded ->
#                tests-run). It is externally observable, survives process
#                death, and costs zero tokens to coordinate. An in-memory
#                graph does none of those.
#   langsmith  - installed only as a transitive dependency of langchain-core.
#                Cost/token tracking is agents/usage_ledger.py, which posts
#                [LLM-USAGE] straight onto the Jira story.
#   vector DBs / embeddings / RAG - retrieval here is EXACT, not semantic:
#                component filtering picks the pages, AST extraction gives real
#                method signatures, SHA-256 markers detect changed test cases.

# langchain-core — message types (SystemMessage / HumanMessage).
langchain-core>=1.0,<2.0

# ChatOpenAI — the HTTP client. Accepts base_url, so it works with ANY endpoint
# following the OpenAI /v1/chat/completions spec (the adesso LiteLLM gateway,
# Azure, self-hosted models). Switching provider is config, never code.
langchain-openai>=0.3.0

# Pydantic — data validation library used everywhere in our agents.
# Defines the SHAPE of LLM outputs so we never trust raw text from the LLM.
# If the model returns malformed data, Pydantic raises a clear error.
pydantic>=2.9

tenacity>=8.0
